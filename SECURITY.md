# Политика безопасности

## Поддерживаемые версии

Исправления безопасности готовятся для текущего состояния `main` и следующей beta-версии. Старые APK и произвольные сборки из веток не поддерживаются.

## Как сообщить об уязвимости

Используйте **Security → Report a vulnerability** в GitHub, если private vulnerability reporting включён для репозитория. Не создавайте публичный issue с рабочим exploit, паролем, hub ID, адресом, токеном, данными здоровья или signing-материалом.

Если приватная форма недоступна, создайте публичный issue без технических деталей и попросите сопровождающего предложить закрытый канал. Не прикладывайте секреты даже в замаскированном архиве.

В сообщении полезны:

- версия приложения или SHA коммита;
- версия Android и модель устройства;
- локальный или облачный режим без реальных адресов;
- краткое описание влияния;
- безопасные шаги воспроизведения с фиктивными значениями.

## Что считается чувствительными данными

- пароли, токены, signing-key и keystore;
- серийный номер или другой идентификатор хаба;
- e-mail учётной записи;
- локальные и публичные IP/домены пользователя;
- имена комнат, устройств и сценариев;
- данные Health Connect;
- полные логи и дампы приложения без ручной очистки.

При случайной публикации секрета сначала отзовите или смените его. Удаление только из последнего коммита недостаточно: значение останется в истории Git.

## Граница доверия

Облачный endpoint обязан использовать `wss://`. Локальный `ws://` технически разрешён для private/LAN-адресов, но не шифрует трафик. Используйте его только в доверенной сети. APK для стабильного релиза должен быть подписан постоянным ключом сопровождающего и сопровождаться SHA-256.
