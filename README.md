# SprutHub.Helper

Неофициальное Android-приложение для управления устройствами SprutHub из системной панели Android и быстрых настроек.

> Проект не связан с разработчиками SprutHub. Приложение использует внутренний WebSocket/JSON-RPC-протокол, который может измениться без предупреждения. Текущая версия — [`0.3.0-beta.1`](https://github.com/nikitau-svg/SprutHub.Helper/releases/tag/v0.3.0-beta.1). Старый `v0.1.0` собран до удаления персональной конфигурации и не должен распространяться.

## Что уже работает

- подключение к локальному или настроенному облачному адресу SprutHub;
- режим «Авто»: сначала локальное соединение, затем облачное;
- устройства и сценарии в Android Device Controls;
- до 12 назначаемых плиток быстрых настроек с отдельной проверкой, действительно ли плитка добавлена Android;
- пользовательские PNG-иконки для Android Device Controls и плиток;
- локальный кэш каталога и обновление состояний через WebSocket;
- отдельные локальный и облачный пароли;
- чтение выбранных показателей Health Connect;
- создание виртуального аксессуара «Здоровье» в SprutHub только по явной команде пользователя;
- отдельное устройство «Телефон» с независимым выбором датчиков батареи, питания, сети, системы и хранилища;
- событийная отправка зарядки, сети, экрана и энергосбережения в постоянном режиме плюс настраиваемый опрос;
- несколько геозон с собственным радиусом, устройством присутствия и необязательным расстоянием до точки;
- ручная и фоновая синхронизация здоровья, телефона и геозон.

Поддерживаемые показатели здоровья: шаги, пульс, пульс в покое, сон, вес, SpO₂, систолическое и диастолическое давление, активные калории, дистанция, температура тела, частота дыхания и HRV. Показатели телефона больше не смешиваются с аксессуаром здоровья.

## Ограничения

- Требуется Android 11 или новее.
- Доступность Health Connect и фонового чтения зависит от версии Android, устройства и выданных разрешений.
- Вид и доступность Device Controls и плиток зависят от прошивки производителя. Работа на всех оболочках не гарантируется.
- Не каждый сервис SprutHub обязательно распознаётся как управляемое устройство.
- Внутренний протокол SprutHub не является публично стабилизированным API. Обновление хаба может нарушить совместимость.
- Android может задерживать 15-минутную фоновую задачу. После принудительной остановки приложения она не возобновится до следующего запуска.
- Для надёжных геозон Android должен получить точную геопозицию и доступ «Всегда»; прошивка всё равно может задержать событие на несколько минут.

## Установка APK

Для обычной установки скачайте **подписанный** APK из проверенного [`v0.3.0-beta.1`](https://github.com/nikitau-svg/SprutHub.Helper/releases/tag/v0.3.0-beta.1) и сверьте его с приложенным SHA-256. Не используйте опубликованный `v0.1.0`: он собран из старого состояния с персональными значениями по умолчанию и не имеет отдельного файла контрольной суммы.

Артефакт beta-workflow и опубликованный beta-prerelease — тестовые сборки, подписанные постоянным закрытым ключом сопровождающего через GitHub Secrets. Поэтому они обновляют предыдущую beta без удаления приложения и потери настроек. Неподписанный release candidate из draft-релиза установить нельзя; публиковать его как готовый APK не следует.

При ручной установке Android попросит разрешить установку из выбранного источника. Сверьте SHA-256 с файлом контрольной суммы релиза и не устанавливайте APK из сторонних сообщений или зеркал.

## Первая настройка

1. Откройте приложение и выберите режим: «Авто», «Дом» или «Облако».
2. Укажите серийный номер хаба, локальный адрес и локальный пароль.
3. Для облачного режима укажите e-mail, облачный пароль и один из предложенных серверов либо собственный `wss://`-адрес.
4. Нажмите **Сохранить, проверить и загрузить**.
5. Для Device Controls нажмите **В панель** у нужного устройства.
6. Для быстрой настройки нажмите **Добавить плитку**. Назначение устройства и фактическое добавление плитки Android показываются раздельно. На Android 11–12 плитка добавляется через обычное редактирование шторки.

Локальный адрес можно указывать как IP, имя `.local` или полный WebSocket-адрес. Незашифрованный `ws://` разрешён приложением только для локальных/private-адресов. Используйте его только в доверенной домашней сети.

## Здоровье, телефон и присутствие

1. В карточке **Здоровье** выберите показатели и комнату SprutHub.
2. Выдайте только нужные разрешения Health Connect.
3. Нажмите **Создать устройство в SprutHub**. До этого приложение не создаёт виртуальный аксессуар.
4. При необходимости разрешите фоновое чтение и снимите ограничения батареи для приложения.

В карточке **Телефон** отдельно выберите, какие сведения публиковать, и режим работы: экономичный периодический либо постоянный с быстрыми событиями. Для постоянного режима разрешите уведомления и добавьте приложение в Samsung **Никогда не спящие приложения**.

В карточке **Присутствие** можно создать несколько именованных зон. Для каждой задаются координаты, радиус, комната SprutHub и публикация расстояния. Координаты зон хранятся только на телефоне; в SprutHub отправляются состояние присутствия и, по выбору пользователя, расстояние.

Показатели здоровья отправляются только на настроенный **локальный** адрес хаба. Облачный fallback для них отключён. Если локальный хаб недоступен, фоновая задача завершится ошибкой и будет повторена позднее.

## Приватность

В отслеживаемых Git-файлах текущей версии нет пользовательского серийного номера, LAN-IP, e-mail, пароля или signing-keystore. Настройки вводятся на телефоне. Ранние коммиты содержат удалённые позднее персональные идентификаторы; это отдельно отмечено в [отчёте аудита](docs/REPOSITORY_AUDIT.md).

| Данные | Где хранятся или передаются |
|---|---|
| Локальный и облачный пароли | Зашифрованы AES-GCM; ключ хранится в Android Keystore |
| Адреса, hub ID и e-mail | В закрытом хранилище приложения на телефоне |
| Каталог устройств, назначения плиток, геозоны и привязки виртуальных устройств | Локально в каталоге приложения |
| Данные Health Connect | Читаются после разрешения и отправляются только на локальный хаб |
| Данные входа | Передаются выбранному локальному или облачному endpoint для авторизации |

Резервное копирование и перенос данных приложения отключены. В текущем коде нет SDK аналитики, рекламы и crash-reporting. При использовании локального `ws://` трафик не шифруется на уровне WebSocket, поэтому сеть должна быть доверенной. Для облачного адреса приложение требует `wss://`.

## Как устроено подключение

Обычное управление использует выбранный режим:

```text
Android -> локальный SprutHub
           └─ при ошибке в режиме «Авто» -> настроенный облачный SprutHub

Health Connect -> только локальный SprutHub
Телефон/геозоны -> режим подключения пользователя (local/cloud/auto)
```

Отдельный REST-мост, Node-RED или внешний сервер приложению не нужен. Для виртуального аксессуара приложение получает реальные `aId/sId/cId` от хаба и сохраняет их локально.
