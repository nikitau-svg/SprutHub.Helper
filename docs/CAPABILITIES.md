# Возможности и ограничения

Этот документ описывает `0.8.0-beta.2`. SprutHub.Helper использует внутренний WebSocket/JSON-RPC-протокол SprutHub, поэтому совместимость может измениться после обновления хаба.

Обозначения: ✅ поддерживается; ⚠️ зависит от Android, оболочки или конфигурации; — пока не поддерживается.

## Подключение

| Возможность | Статус | Примечание |
|---|---:|---|
| Локальный SprutHub | ✅ | IP, имя `.local`, `ws://` или `wss://`; незашифрованный `ws://` разрешён только для private/LAN-адресов |
| Облако актуальной beta-линии SprutHub | ✅ | Предустановки `.ru`/`.com` и собственный `wss://`-адрес |
| Режим `Авто` | ✅ | Выбирает порядок local/cloud по текущей сети и использует резервный endpoint при ошибке |
| Разные локальный и облачный пароли | ✅ | Пустое поле при редактировании сохраняет уже записанный пароль |
| Проверка до сохранения | ✅ | Новый адрес и пароль принимаются только после входа и чтения каталога |
| Старый не-beta облачный вход | — | Требует отдельного исследования реального протокола |
| Собственный сервер Helper | Не нужен | Приложение связывается с выбранным SprutHub напрямую |

## Интерфейсы Android

| Интерфейс | Статус | Реальное поведение |
|---|---:|---|
| Каталог в приложении | ✅ | Комнаты, аксессуары, сервисы и сценарии; многопараметрический сервис раскрывает полный список распознанных характеристик |
| Быстрые кнопки в шторке | ✅ | До 12 слотов; проверка SprutHub при раскрытии шторки; read-only датчик ставит значение в основной заголовок для оболочек, скрывающих вторую строку |
| Виджеты рабочего стола | ⚠️ | До восьми объектов в одном экземпляре, готовые шаблоны и ручная компоновка; наличие, число ячеек и размеры определяет launcher |
| Панель устройств из шторки | ⚠️ | Стандартный Android Device Controls-провайдер; место входа и оформление определяет оболочка |
| Раскрытая панель Helper | ⚠️ | До 48 карточек; собственный адаптивный экран доступен из приложения и через совместимую системную панель на Android 14+ |
| Пользовательские PNG-иконки | ✅ | Для виджетов, плиток и панелей; квадратный PNG с прозрачностью даёт наиболее предсказуемый результат |

Все интерфейсы используют общий каталог и единые состояния `Онлайн / Недавно обновлено / Обновление / Устарело / Нет связи`. Точные интервалы и ограничения описаны в [контракте актуальности](INTERFACE_FRESHNESS.md).

Встроенный раздел **Настройки → Как управлять** оценивает не абстрактную поддержку Android, а доступность каждой поверхности на текущем телефоне:

- **Проверено** — этот вариант прошёл аппаратный прогон на указанной модели и оболочке;
- **Зависит от оболочки** — Android API доступен, но launcher или производитель определяет форму, размеры и место входа;
- **Ограничено** — работает совместимый вариант без части возможностей новой версии Android;
- **Недоступно** — устройство не объявляет необходимую системную функцию; внутренний экран Helper может оставаться доступен.

На Android 11–12 быстрая кнопка добавляется вручную через редактирование шторки. Android 13+ разрешает приложению показать системный запрос добавления. Точная responsive-компоновка виджета используется на Android 12+, а Android 11 получает совместимый размерный fallback. Собственная раскрытая панель внутри Device Controls требует Android 14+ и всё равно может быть проигнорирована оболочкой.

## Формы управления SprutHub

| Тип | Статус |
|---|---:|
| Переключатель `вкл/выкл` | ✅ |
| Числовой диапазон: яркость, положение, скорость, температура | ✅ |
| Питание вместе с одним основным диапазоном | ✅ |
| Сценарий или импульсная кнопка | ✅ |
| Датчик только для чтения | ✅ |
| Несколько независимых кнопок одного аксессуара | ✅, отдельными карточками |
| Связанные датчики одного управляющего сервиса | ✅, показателями общей карточки |
| Записываемое перечисление режимов с `validValues` | ✅ выбор в крупной панели Helper; плитка и виджет безопасно открывают приложение |
| Несколько независимых диапазонов в одной карточке | — |
| Камеры, медиавходы и сложные медиакоманды | — |

Правила идентичности и группировки приведены в [описании каталога](SPRUTHUB_CATALOG.md).

## Телефон, здоровье и присутствие

| Возможность | Статус | Примечание |
|---|---:|---|
| Виртуальное устройство телефона | ✅ | Пользователь сам выбирает публикуемые датчики; обязательным остаётся только служебный heartbeat |
| Быстрые события телефона | ⚠️ | Реальные изменения процента/состояния зарядки, сети, экрана, звука, DND, будильника и энергосбережения отправляются по событию в постоянном режиме; непрерывные ток/мощность/напряжение обновляет опрос |
| Страховочный опрос телефона | ✅ | WorkManager планируется минимум раз в 15 минут, но Android может задержать запуск |
| Локальное предупреждение о застывшей синхронизации | ✅ | Работает, пока Android способен запускать приложение |
| Защитный сценарий в SprutHub | ✅ | Проверяется на дубли и восстанавливается при следующем запуске Helper; уведомление настраивается в самом хабе |
| Health Connect | ⚠️ | Не привязан к Samsung Health: подходит любой источник, записывающий выбранные типы данных в Health Connect |
| Фоновое чтение здоровья | ⚠️ | Зависит от Android, версии Health Connect и разрешения фонового чтения |
| Отправка здоровья через облако | — | Значения здоровья публикуются только на настроенный локальный SprutHub |
| Несколько геозон | ✅ | Для каждой задаются точка, радиус, комната, присутствие и необязательное расстояние |
| Геозоны после перезагрузки | ⚠️ | Helper перерегистрирует их, но требуются точная геопозиция и доступ `Всегда` |

## Что приложение не может гарантировать

- WebSocket внутри телефона не способен разбудить приложение после системного `Force stop`.
- Android и прошивка производителя могут задерживать WorkManager, геозоны и обновление виджета.
- Открытие шторки запускает код Helper, а не встроенный клиент SprutHub внутри Android.
- Сценарий в хабе может предупредить о пропавшем heartbeat, но не может удалённо снять `Force stop` с Android-приложения.
- Удалённое вручную виртуальное устройство восстанавливается только явной пользовательской операцией; фоновая задача не создаёт его исподтишка.

Перед сообщением об ошибке проверьте [FAQ](FAQ.md) и подготовьте [безопасный диагностический отчёт](DIAGNOSTICS.md).
