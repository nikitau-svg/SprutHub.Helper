# Аудит репозитория перед публичным открытием

Дата среза: 2026-08-30. Проверены текущее отслеживаемое дерево, доступные локальные ветки и все достижимые локальные коммиты на момент проверки. Проверка включала поиск e-mail, private IPv4, длинных hex/base64-строк, типичных имён секретов, signing-файлов, APK, архивов, баз данных и крупных blob. Специализированный gitleaks/trufflehog в окружении отсутствовал, поэтому результат не является криптографическим доказательством отсутствия секретов.

## Текущее дерево

- Закоммиченных APK, AAB, keystore, сертификатов, `.env`, дампов, логов и баз данных не найдено.
- Реальных пользовательских e-mail, LAN-IP, hub ID, паролей и токенов не найдено.
- Совпадения в unit-тестах используют очевидные фиктивные значения и зарезервированные тестовые домены/private-сети.
- `.gitignore` исключает build/IDE-файлы, APK, captures и распространённые форматы keystore.
- Origin использует SSH URL без встроенного токена.
- В приложении не найдены SDK рекламы, аналитики или crash-reporting.
- В основном локальном checkout присутствуют игнорируемые `SprutHub.Helper.apk` и `.signing/spruthub-helper.p12`. Они не отслеживаются Git, но keystore нужно хранить вне каталога проекта и исключать при ручной упаковке папки в архив.

## История и локальная Git-метаинформация

- В ранних коммитах присутствовали конкретный 16-символьный идентификатор хаба и конкретный LAN-IP. Из текущего дерева они удалены, но остаются доступны в истории.
- Тег и Release `v0.1.0` указывают на commit `1973a29`, в котором эти значения ещё присутствуют в README и исходном значении `DEFAULT_SERIAL`. Поэтому опубликованный APK нужно считать содержащим персональную конфигурацию и убрать до открытия репозитория.
- В author/committer metadata есть обычный персональный e-mail и локальный адрес рабочей станции. GitHub noreply используется не во всех коммитах.
- Пароли, токены, signing-key и keystore в достижимых объектах шаблонным поиском не обнаружены.
- Дополнительный поиск по всей общей object database не нашёл шаблонов private key или распространённых API-токенов. Персональный hub ID присутствует также в недостижимых blob. Такие объекты не попадают при обычном push, но попадут в ручную копию всей папки `.git`.
- В общей локальной object database нескольких worktree Git сообщает о недостижимых commits/trees/blobs и одном служебном garbage-файле. Очистка не выполнялась, чтобы не затронуть параллельную работу.
- Ветки `codex/two-passwords` и `fix/ui-readability` ответвлены от старого коммита и отстают от `main`; каждую нужно пересмотреть отдельно, а не сливать вслепую.
- Локальная ветка `beta` отсутствует. На GitHub есть тег и опубликованный Release `v0.1.0` с APK, но без отдельной SHA-256 checksum.

## Состояние GitHub

- Репозиторий приватный, ветка по умолчанию — `main`; описание заполнено, wiki выключена, issues включены.
- Ветки `main`, `codex/two-passwords` и `fix/ui-readability` не защищены; `beta` ещё не создана.
- На момент проверки сохранены 10 устанавливаемых debug APK как Actions artifacts. Четыре из них собраны из commits `cc264a4`, `0b6a6b1`, `1973a29` и `5d7be91`, где персональный hub ID ещё находился в исходниках; их следует удалить. Все артефакты автоматически истекут 2026-09-29.
- В Actions настроены четыре signing-secret: base64-keystore, alias и два пароля. Они используются только доверенным beta-workflow, чтобы обновления устанавливались поверх существующей версии без удаления данных; pull request доступа к ним не получает.
- Rulesets для приватного репозитория недоступны на текущем плане GitHub. API предлагает либо подходящий платный план, либо публичную видимость; до осознанного изменения видимости защита веток останется организационным правилом.

## Остаточные риски и решения владельца

1. **Исторические идентификаторы.** По условию задачи история не переписывалась. До публичного открытия владелец должен решить, допустима ли их раскрываемость. Если нет, нужна отдельная согласованная процедура history rewrite, ротация доступных учётных данных и координация со всеми клонами.
2. **Персональные e-mail в истории.** Их нельзя исправить новым коммитом. Для будущих коммитов следует включить GitHub noreply и проверить `git config user.email`.
3. **Некоммерческая лицензия.** После аудита проект получил PolyForm Noncommercial License 1.0.0. Она разрешает некоммерческое использование, изменение и распространение, но не является Open Source в определении OSI и не даёт прав на интеллектуальную собственность SprutHub или сторонних компонентов.
4. **Нет Gradle Wrapper.** CI фиксирует Gradle 8.11.1, но локальная воспроизводимость зависит от установленного Gradle. Wrapper относится к build-файлам и намеренно не добавлялся в этой задаче.
5. **Actions используют version tags.** Для более строгой защиты supply chain действия можно закрепить на проверенных full commit SHA отдельным изменением после проверки upstream.
6. **Старые CI-артефакты и Release.** Исходные commits подтверждают попадание персональной конфигурации в `v0.1.0` и четыре Actions-сборки. Их нужно удалить до открытия репозитория; чистые поздние APK всё равно следует перепроверить или дождаться автоматического истечения.

## Исправлено этим патчем

- Доступ signing-секретов ограничен push-сборками доверенных веток; pull request собирается без них.
- Beta и release candidate разделены по назначению.
- Release workflow создаёт только draft с явно неподписанным candidate; публичная публикация требует локальной подписи и ручной проверки.
- Добавлены публичные правила приватности, безопасности, веток, вкладов и выпусков.

## Проверки перед изменением видимости

- Запустить специализированный secret scanner по всей истории из доверенного окружения.
- Проверить GitHub Actions logs и старые artifacts: они не входят в git-аудит.
- Проверить Issues, pull requests, wiki, Releases и Packages на персональные данные и APK.
- Включить private vulnerability reporting, secret scanning и push protection, если они доступны.
- Настроить rulesets для `main`, `beta` и `v*`.
- Проверить актуальность `LICENSE`, `NOTICE` и уведомлений о сторонних компонентах перед каждым публичным выпуском.
