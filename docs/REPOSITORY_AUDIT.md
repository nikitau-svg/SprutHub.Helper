# Аудит репозитория перед публичным открытием

Дата среза: 2026-08-30. Проверены текущее отслеживаемое дерево, доступные локальные ветки и все 19 достижимых коммитов. Проверка включала поиск e-mail, private IPv4, длинных hex/base64-строк, типичных имён секретов, signing-файлов, APK, архивов, баз данных и крупных blob. Специализированный gitleaks/trufflehog в окружении отсутствовал, поэтому результат не является криптографическим доказательством отсутствия секретов.

## Текущее дерево

- Закоммиченных APK, AAB, keystore, сертификатов, `.env`, дампов, логов и баз данных не найдено.
- Реальных пользовательских e-mail, LAN-IP, hub ID, паролей и токенов не найдено.
- Совпадения в unit-тестах используют очевидные фиктивные значения и зарезервированные тестовые домены/private-сети.
- `.gitignore` исключает build/IDE-файлы, APK, captures и распространённые форматы keystore.
- Origin использует SSH URL без встроенного токена.
- В приложении не найдены SDK рекламы, аналитики или crash-reporting.

## История и локальная Git-метаинформация

- В ранних коммитах присутствовали конкретный 16-символьный идентификатор хаба и конкретный LAN-IP. Из текущего дерева они удалены, но остаются доступны в истории.
- В author/committer metadata есть обычный персональный e-mail и локальный адрес рабочей станции. GitHub noreply используется не во всех коммитах.
- Пароли, токены, signing-key и keystore в достижимых объектах шаблонным поиском не обнаружены.
- В локальной object database Git сообщает о небольшом недостижимом служебном объекте/garbage. Он не является отслеживаемым файлом и не должен попасть при обычном push; удаление не выполнялось.
- Ветки `codex/two-passwords` и `fix/ui-readability` ответвлены от старого коммита и отстают от `main`; каждую нужно пересмотреть отдельно, а не сливать вслепую.
- Ветка `beta` и version tags отсутствовали на момент аудита.

## Остаточные риски и решения владельца

1. **Исторические идентификаторы.** По условию задачи история не переписывалась. До публичного открытия владелец должен решить, допустима ли их раскрываемость. Если нет, нужна отдельная согласованная процедура history rewrite, ротация доступных учётных данных и координация со всеми клонами.
2. **Персональные e-mail в истории.** Их нельзя исправить новым коммитом. Для будущих коммитов следует включить GitHub noreply и проверить `git config user.email`.
3. **Нет LICENSE.** Публичный просмотр кода не даёт права на его повторное использование. Лицензию должен осознанно выбрать владелец; она не добавлена автоматически.
4. **Нет Gradle Wrapper.** CI фиксирует Gradle 8.11.1, но локальная воспроизводимость зависит от установленного Gradle. Wrapper относится к build-файлам и намеренно не добавлялся в этой задаче.
5. **Actions используют version tags.** Для более строгой защиты supply chain действия можно закрепить на проверенных full commit SHA отдельным изменением после проверки upstream.

## Исправлено этим патчем

- Удалена зависимость GitHub Actions от base64-keystore и четырёх signing-секретов.
- Beta и release candidate разделены по назначению.
- Release workflow создаёт только draft с явно неподписанным candidate; публичная публикация требует локальной подписи и ручной проверки.
- Добавлены публичные правила приватности, безопасности, веток, вкладов и выпусков.

## Проверки перед изменением видимости

- Запустить специализированный secret scanner по всей истории из доверенного окружения.
- Проверить GitHub Actions logs и старые artifacts: они не входят в git-аудит.
- Проверить Issues, pull requests, wiki, Releases и Packages на персональные данные и APK.
- Включить private vulnerability reporting, secret scanning и push protection, если они доступны.
- Настроить rulesets для `main`, `beta` и `v*`.
- Выбрать LICENSE или явно оставить репозиторий source-available без разрешения на повторное использование.
