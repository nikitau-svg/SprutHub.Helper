# Аудит публичного репозитория

Дата актуального среза: 2026-09-02. Репозиторий уже публичный; этот документ описывает текущее состояние ветки `beta` и оставшиеся действия перед переносом её в `main`.

## Текущее дерево

- В отслеживаемых файлах нет APK/AAB, keystore, signing-сертификатов, `.env`, логов или баз данных.
- В текущем исходном дереве не найдены реальные пароли, токены, адреса пользователя, серийный номер хаба или абсолютные пути рабочей машины.
- Gradle Wrapper находится в репозитории, а CI использует зафиксированную версию JDK и Android SDK.
- Origin использует SSH URL без встроенного токена. Текущие коммиты создаются с GitHub `noreply` e-mail.
- Настройки, каталог устройств и учётные данные вводятся на телефоне и не входят в APK как значения по умолчанию.
- Локально могут находиться игнорируемые APK и signing-файлы. Они не входят в Git, однако нельзя прикладывать всю папку проекта к issue или архивировать её без отдельной проверки.

## Автоматическая защита

Скрипт `scripts/check-public-tree.sh` запускается в Android CI, beta-публикации и стабильном release workflow. Он останавливает сборку при наличии:

- отслеживаемых APK, signing-файлов, логов, баз данных или `.env`;
- шаблонов private key, распространённых токенов и Telegram bot token;
- абсолютных путей `/Users/...`, `/var/folders/...` или Windows user profile;
- похожего на реальный 16-символьного hub ID в URL;
- непустого жёстко заданного `DEFAULT_SERIAL`/`DEFAULT_HUB_ID`;
- битых локальных Markdown-ссылок.

Это дополнительный предохранитель, а не доказательство отсутствия любого возможного секрета. Перед публикацией диагностик всё равно нужно пользоваться безопасным отчётом приложения и просматривать вложение.

## Ветки и релизы

- Публичная ветка по умолчанию — `main`.
- Разработка и beta-релизы идут в постоянной ветке `beta`.
- `beta` содержит актуальную линию `0.7` и опережает стабильный исходный код в `main`. Публичный prerelease `0.7.0-beta.5` собран из этой ветки; стабильный код переносится в `main` только после завершения 0.7 и финального аппаратного E2E.
- Теги начинаются с `v0.3.0-beta.1`; устаревшего тега и релиза `v0.1.0` больше нет.
- На remote остаются старые рабочие ветки `build/0.3.0-beta.8`, `codex/two-passwords` и `fix/ui-readability`. Их нельзя сливать вслепую; удаление выполняется отдельным осознанным действием после проверки, что полезные изменения уже находятся в `beta`.

## История Git

Ранние коммиты содержали удалённые позднее персональные идентификаторы и некоторые персональные author/committer e-mail. Их нет в текущем APK и текущем дереве, но они остаются в публичной истории Git.

Переписывание истории сознательно отложено владельцем до отдельного решения перед более широким анонсом проекта. Если любое историческое значение давало доступ, его необходимо считать раскрытым и сменить независимо от возможной последующей очистки истории. History rewrite потребует резервной копии, координации всех клонов и принудительного обновления веток и тегов.

## Перед переносом `beta` в `main`

1. Собрать финальный подписанный кандидат 0.7 в GitHub Actions и убедиться, что сертификат совпадает с опубликованной `0.7.0-beta.5`.
2. Установить кандидат поверх предыдущей beta без очистки данных и проверить миграцию onboarding, назначений и виртуальных устройств.
3. Пройти аппаратную матрицу: local, cloud beta, fallback, виджет, плитка, Device Controls, крупная панель, телефон, Health Connect и геозоны.
4. Проверить потерю сети, смерть процесса, перезагрузку, Doze и восстановление назначений без дублей.
5. Сделать актуальные обезличенные скриншоты на телефоне и добавить их по [чек-листу](SCREENSHOTS.md).
6. Проверить GitHub Security settings, Actions artifacts и необходимость старых remote-веток.
7. Открыть контролируемый pull request `beta` → `main`; не перемещать beta-теги и не публиковать стабильный релиз до зелёного CI и ручной проверки.
